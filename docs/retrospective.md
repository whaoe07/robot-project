# 项目复盘：MuJoCo 抓取 + ACT

> 这份文档记录“实际发生了什么”，包括走过的弯路。面试时讲项目，照这个顺序讲。

## 1. 目标

2028 届求职，目标岗位是具身智能/机器人工程岗。用一个端到端项目证明四件事：

- 能在仿真里搭环境
- 能造专家数据
- 能训练模仿学习策略
- 能设计评估、解释数字

## 2. 时间线

| 阶段 | 做了什么 | 结果 |
|---|---|---|
| 环境 | WSL2 + MuJoCo + VS Code Remote | 能跑通渲染和视频 |
| 场景 | `scene_pick.xml`：Franka + 桌子 + 5cm 方块 | 可视化正常 |
| 专家 | 阻尼最小二乘 IK + 3 个路标 + 夹爪时序 | 100% 抓取成功 |
| 数据 | 100 条 episode，20Hz，128×128 图像 + 9 维 qpos + 8 维动作 | 约 5800 帧 |
| 基线 | 单帧 MLP 行为克隆 | 30% |
| 改进 1 | 加 4 帧 qpos 历史 + 修正动作错位 | 5%（更差） |
| 改进 2 | CNN 保留 4×4 空间特征 | 30% |
| 弯路 | 放慢专家 + 加停顿，重采 200 条 | 3.3%（更差） |
| 换模型 | ACT-lite（图像历史 + Transformer + 16 步动作块） | 严格 43%，保持 84% |
| 修正判据 | 成功 = 结束时 `final_z > 0.47` | 84%（50 次） |

## 3. 技术栈

- 仿真：MuJoCo 3.17，MJCF，EGL 离屏渲染
- 语言：Python 3.10
- 深度学习：PyTorch 2.5.1 + CUDA 12.1，RTX 3080 12GB
- IK：阻尼最小二乘 `Jᵀ(JJᵀ + λI)⁻¹ e`
- 数据：20Hz，128×128 RGB，qpos 9 维，action 8 维
- 模型：ACT-lite，CNN + Transformer encoder/decoder，chunk=16，history=4
- 训练：L1 loss，AdamW，60 epochs，batch 64
- 评估：闭环，exec_k=8，50 次随机位置

## 4. 遇到的困难与解决

| 困难 | 现象 | 解决 |
|---|---|---|
| MuJoCo 窗口黑屏 | 任务栏有窗口但看不到内容 | 改用 EGL 离屏渲染，视频代替窗口 |
| GitHub clone 中断 | `GnuTLS recv error` | `--depth 1 --filter=blob:none --sparse` |
| WSL 内存不足 | 加载全部图像被 OOM kill | 逐集读取，只累加统计量 |
| IK 边界爆炸 | 目标不可达时 `dq` 涨到 5.7 | 加 damping 1e-3 |
| 分布偏移 | 训练 loss 低但成功率低 | 换 ACT，加历史帧和动作块 |
| 停顿数据稀释信号 | val 0.0119 但成功率 3.3% | 放弃该批数据，回到 fast 数据 |
| 代码没同步 | 服务器训练结果和上次一模一样 | scp 后 grep 标志确认 |
| 判据不合理 | 大量 0.49–0.50 被判失败 | 改为 `final_z > 0.47` |

## 5. 参数调整记录

| 变量 | 尝试 | 结果 | 结论 |
|---|---|---|---|
| epochs | 30 → 60 | val 0.060 → 0.047，成功率 10% → 0% | 更多 epoch 不等于更好 |
| 历史帧 | 1 → 4 帧 qpos | 成功率 30% → 5% | 单独加历史不够 |
| CNN 池化 | 1×1 → 4×4 | val 0.056 → 0.041，成功率 30% | 空间信息重要 |
| 数据速度 | 0.5 → 0.3 + 停顿 | 成功率 3.3% | 停顿稀释了关键帧信号 |
| 模型 | MLP → ACT | 严格 43%，保持 84% | 时序 + 动作块是关键 |
| exec_k | 4 / 8 / 16 | 73% / 77% / 30% | 闭眼太久会漂 |
| 成功判据 | max_z>0.5 → final_z>0.47 | 43% → 84% | 判据要匹配任务定义 |

## 7. 做对了什么

- 先让专家 100% 可靠，再采数据
- 闭环评估，不用开环数字骗自己
- 每次只改一个变量，记录结果
- 失败样本保留分析，不隐藏

## 8. 可以更好

- 数据多样性：边缘位置加权采样
- temporal ensemble：减少抖动、提高成功率
- sim2real：域随机化、执行器建模
- 时延实验：通信背景的差异化方向，还没做

## 9. 面试问答准备

**Q：为什么用 IK 生成专家，不用强化学习？**

A：任务固定、环境可控，IK 能稳定产出 100% 成功的演示，数据成本低；RL 需要设计奖励、训练不稳定，不适合快速搭基线。

**Q：为什么 ACT 比行为克隆好？**

A：ACT 看多帧历史，能区分“正在下降”和“正在抬起”；一次输出 16 步动作块，减少逐步决策的复合误差；Transformer 能建模动作之间的依赖。

**Q：怎么评估的？**

A：闭环评估，策略自己看自己动；每 8 步重规划；50 次随机方块位置；成功定义为结束时方块仍被夹持在 0.47 米以上。

**Q：最大的失败是什么？**

A：试过放慢专家、加停顿、采 200 条，结果 val loss 降到 0.012，成功率反而掉到 3.3%。原因是停顿让大量“静止帧”主导了 loss，关键动作被稀释。教训是 loss 低不等于控制好，评估必须闭环。

**Q：sim2real 怎么做？**

A：域随机化（质量、摩擦、电机延迟）、执行器建模、传感器噪声；先在小范围验证，再逐步扩大。

### 10.1 需要修正的四处

| 我写的 | 准确的说法 |
|---|---|
| 分布偏移和边缘误差是一个东西 | 不是。分布偏移是全局现象；边缘误差是其中一个来源 |
| 一开始只用 MLP，后来加 CNN | 基线一直是 CNN + MLP；改的是 CNN 的池化方式，1×1 → 4×4 |
| ACT 的增益是因为加了 chunk | 是三样一起：图像历史 + Transformer + 动作块 |
| 0.05 是动作步，0.8 是物理步 | 0.05 秒是动作步（25 个物理步）；0.8 秒是一个 chunk（16 个动作步） |

### 10.2 修正说明

**分布偏移 vs 边缘误差**

- 分布偏移：策略自己跑时，看到的状态不在训练数据里，误差会累积。它是全局现象，中间位置也会发生。
- 边缘误差：在工作空间边缘，手离关节远、雅可比病态，同样的关节误差会放大成更大的位置误差；同时边缘样本更少。
- 关系：边缘误差是分布偏移的一个具体来源，不是同一个东西。

**模型演进**

- 基线：CNN + MLP，不是纯 MLP。
- 第一次改：CNN 最后从 `AdaptiveAvgPool2d(1)` 改成 `AdaptiveAvgPool2d(4)`，保留 4×4 空间信息。
- 第二次改：换成 ACT（CNN + Transformer），同时引入图像历史、时序建模、动作块。

**ACT 的三样东西**

1. 图像历史：看最近 4 帧，能区分“正在下降”和“正在抬起”。
2. Transformer：让不同帧、不同动作之间互相参考。
3. 动作块：一次输出 16 步，减少逐步决策的次数和复合误差。

只加 chunk、不加历史和 Transformer，效果不会一样。

**时间单位**

```
0.002 秒 = 1 个物理步（一次 mj_step）
25 个物理步 = 1 个动作步 = 0.05 秒
16 个动作步 = 1 个 chunk = 0.8 秒
```

0.8 秒是 chunk 的时长，不是“物理步”。

另外，`k` 控制的是“观察、重新预测”的频率，不是“验证”。

### 10.3 修正后的版本

> 这个项目我从 MuJoCo 搭场景开始，用 IK 写了一个 100% 成功的专家，采了 100 条演示数据。模型一开始是 CNN + MLP，只能用到全局特征，成功率 30%；把 CNN 的池化从 1×1 改成 4×4、保留空间信息后，还是 30%；换成 ACT（图像历史 + Transformer + 16 步动作块）后，成功率到 84%。
>
> 我理解了分布偏移：策略自己跑会进入训练数据没见过的状态，误差会累积。边缘位置更严重，因为手离关节远、雅可比病态，会把关节误差放大成更大的位置误差。
>
> 评估用闭环，每 8 步重新观察一次。chunk 是 16 步、0.8 秒；k 是实际执行几步，k 越小纠正越频繁，但太小会抖、推理也变慢。
